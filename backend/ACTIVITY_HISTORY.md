# 신청·나눔 내역 (2단계)

`GET /api/mypage/activity`는 JWT 회원의 활동만 반환한다. 요청 본문/쿼리의 회원 ID로 다른 회원의 내역을 조회할 수 없다.

- `donatedPosts`: 내가 작성한 나눔글. 게시글 상태, 이미지, 등록일.
- `sentRequests`: 다른 사람의 물품에 보낸 실제 신청. 상대방, 신청 상태, 날짜, 응답 기한, 기존 채팅방 ID.
- `receivedRequests`: 내 나눔글에 들어온 신청.
- `requestedPosts`: 내가 작성한 ‘필요해요’ 요청글. 실제 거래 신청과 구분.
- `counts.requests`는 보낸 신청 수다. 요청글 수는 `counts.wanted`다.

조회 시 해당 회원과 관련된 만료 요청을 정리한다. 기존 `picked_up`은 화면에서 완료로 표시하고, 채팅방 ID가 없는 이전 신청에는 채팅 버튼을 표시하지 않는다.

앱의 `/my-shares` 화면은 일반회원에게 **내 나눔 / 받은 신청**, 수혜자에게 **내 요청글 / 보낸 신청** 두 탭만 제공한다. 기본 탭과 마이페이지 상단 건수·바로가기도 회원 유형에 맞춘다. 숨겨진 탭을 URL로 지정하더라도 해당 유형의 기본 탭으로 표시한다. 물품별 받은 신청 필터, 상태 표시, 게시글/기존 채팅 이동을 제공한다. 화면 복귀와 새로고침 시 최신 데이터를 조회한다. 채팅방 이동은 신청 생성 API를 호출하지 않는다.

검증: `npm run test:activity:integration` (전용 임시 SQL 데이터 생성·정리), 앱 `tsc --noEmit`.

3~6단계인 알림 이동, 약속 관리, 마음 점수, 관리자 문의는 이 변경 범위에 포함하지 않는다.
