# 회원가입 인증서 QR

QR 내용은 **내부 DB `CERTIFICATION_CODE.code_id`의 숫자**다. 기존 `code` 컬럼과 대조하거나 새 테이블을 만들지 않는다.

## API

- `POST /api/certification/scan`: `multipart/form-data`의 `image` 한 장. QR을 읽고 내부 번호를 검증한다. 사진은 메모리에서 처리하고 저장하거나 공개 업로드 경로에 게시하지 않는다. 최대 10MB, 3천만 픽셀.
- `POST /api/certification/verify`: JSON `{ "code": "123" }`. 직접 입력한 내부 번호를 같은 방식으로 검증한다.
- 성공: `{ "success": true, "data": { "code": "123" } }`. 사전 확인은 번호를 소비하지 않는다.
- `POST /api/members/signup`: 기존 가입 필드와 `isVulnerable: true`, `qr_code: "123"`을 전송한다. 서버가 번호를 다시 확인하고 해당 행을 잠근 뒤 회원 생성과 코드 사용 처리를 함께 커밋한다. 가입 실패 시 함께 롤백한다. 개발 환경에서도 인증 생략은 허용하지 않는다.

## 앱 동작

1. 인증서 사진 선택 또는 촬영 → 자동 인식·DB 조회.
2. 성공하면 인증 완료 표시. 개인정보 입력과 인증 완료 후 동네 설정으로 이동.
3. `QR_NOT_FOUND`, `QR_UNREADABLE`이 합계 2회 발생하면 인증 카드 아래에 번호 입력란과 확인 버튼 표시.
4. 사진 선택 취소, 권한 거절, 통신/서버 오류, 파일 크기 초과, DB에 없는 번호와 사용된 번호는 QR 인식 실패 횟수에 포함하지 않음.
5. 사진을 새로 선택하거나 직접 입력을 수정하면 이전 인증 완료 상태 해제. 선택 취소는 기존 상태 유지.
6. `CERT_USED`는 정확히 **사용된 인증서입니다.** 로 표시. 가입 직전에 다른 가입에서 코드가 사용되어도 다시 확인하고 인증 화면으로 복귀.

직접 입력할 번호는 QR 안의 숫자와 같아야 한다. 인증서를 생성하는 쪽에서도 그 번호를 사람이 읽을 수 있게 표시해야 한다.

## 검증

`npm run test:certification`

- 회전 및 JPEG 압축된 인증서 형태의 이미지 판독, QR 없는 사진, 손상된 이미지, 잘못된 QR 내용.
- 사진/직접 입력이 내부 `code_id`를 조회하며 사전 확인 시 미사용 상태 유지.
- 사용된 인증서 안내, 잘못된 입력, 파일 업로드 제한.
- 같은 코드로 동시 가입 시 1건 성공, 회원 추가 후 오류 발생 시 롤백, 일반회원 가입 유지.
- 통합 테스트는 환경변수의 DB에 독립적인 임시 코드/회원만 만들고 테스트 종료 시 해당 자료만 정리한다.

수동 앱 확인: QR 없는 사진을 두 번 선택해 번호 입력란이 나타나는지, 유효한 내부 번호로 확인한 뒤 입력 수정 시 인증 완료가 해제되는지 확인한다. 실기기 촬영과 권한 동작은 별도 확인이 필요하다.

## 반영

백엔드에 새 의존성 `sharp`, `jsqr` 설치 및 재배포가 필요하다. 프론트는 새 JS 코드로 실행하거나 앱을 다시 빌드해야 한다. DB 구조 변경은 없다.
