# 거래 후기와 마음 점수 (5번)

완료된 거래의 나눔자/수령자가 서로 한 번씩 평가한다. 채팅방 참여 여부뿐 아니라 해당 방에 연결된 PICKUP_REQUEST의 실제 당사자와 완료 상태, 게시글 완료 상태까지 확인한다. 다른 신청이 거절된 뒤 게시글만 완료된 경우에는 평가할 수 없다. 거래 기록이 연결되지 않은 과거 채팅방도 평가를 허용하지 않는다.

## 점수 기준

- 기본 36.5점, 최솟값 0점, 최댓값 100점.
- 앱 ‘매너있어요’는 rating=5로 저장하고 +0.5점.
- 앱 ‘아쉬워요’는 rating=2로 저장하고 −0.5점.
- 기존 1~5점 후기는 4~5점 긍정, 3점 중립, 1~2점 부정으로 집계한다.
- 완료된 거래 당사자 사이의 유효한 후기만 집계한다. 불확실한 과거 후기는 삭제하지 않고 집계에서 제외한다.
- 저장된 후기에서 매번 집계하므로 화면을 열거나 새로고침한다고 점수가 누적되지 않는다. 기존 REVIEW의 게시글 삭제 연쇄 삭제 정책은 그대로 유지하므로 삭제된 후기의 점수는 남지 않는다.

## API/저장

기존 `/api/chats/rooms/:roomId/review-status`, `/api/chats/rooms/:roomId/review` 및 짧은 경로를 유지한다. 서버가 작성자/대상 회원을 결정하며 클라이언트가 보낸 writer/target 값은 사용하지 않는다. 평점은 정수 1~5, 내용은 1~500자. 게시글 행 잠금 후 작성 가능 여부를 다시 검사하고 기존 `uq_review_donate_writer` DB 유일 제약으로 중복 제출을 차단한다. 실패하면 실제 오류를 반환하고 메모리 임시 저장이나 가짜 성공 응답은 사용하지 않는다.

새 인증 API `GET /api/members/:id/reputation`은 score/count/positive/negative/neutral 및 최신 후기 20개를 반환한다. 점수와 개수는 전체 유효 후기를 반영하며 후기 작성자의 개인정보는 반환하지 않는다. 회원 프로필과 본인 마이페이지에서 조회하고, 채팅 목록과 게시글 작성자 점수도 같은 집계 함수를 사용한다.

채팅방 완료 카드의 ‘거래 후기’나 메뉴의 ‘매너 평가하기’에서 서버의 작성 가능 여부를 확인한다. 이미 작성/미완료는 안내를 보여주며 성공 후 채팅 점수를 다시 조회한다. 프로필의 예시 후기·나눔 횟수·응답률은 제거했다. 프로필과 마이페이지 점수는 열거나 다시 진입할 때 갱신한다.

## 검증/배포

`npm run test:reviews:integration`: 테스트용 회원/게시글/신청/Firestore 채팅방만 생성하고 종료 시 해당 데이터만 삭제한다. 완료/당사자 권한, 거절된 신청 차단, 동시 중복 제출, 대상 위조 방지, 양방향 평가, 과거 무관 후기 제외, 실제 채팅 점수를 검증한다.

현재 연결 DB에는 REVIEW 테이블과 필요한 유일 제약이 이미 있어 스키마 변경은 하지 않았다. 다른 환경에서도 해당 제약이 필요하다. Render 배포와 실제 휴대폰 화면 검증은 별도이며 이번 작업에서 진행하지 않았다.
